## 超时：已证明的机制与未证明的系统成因

1. **OAuth 复合用例预算不足已复现。** 原八项再次得到 7 pass / 1 cancelled，原 case 5 为 10008.334ms。两次独立 runtime 初始化分别 5636.233ms、4384.394ms；实际 getAuth 单次低于 0.5 秒，九套目录/seed 写入合计约 20.267ms。Hana fromStorage 使用未缓存的 SDK storage；ModelRuntime.create 的 availability refresh 并发读取凭据，真实文件锁排队，注册 provider 又启动后台 refresh。3806 次 async lock 操作包含重叠工作，不能把各锁耗时相加当墙钟。修复仅把“正常旋转与同 runtime 复用”和“独立 fresh credential 不刷新”拆成两条，各自仍 10 秒且 setup 仍在 test 内；Node 子项 8→9，所有行为断言和真实文件锁保留，生产 auth 未改。
2. **startup receipt 的重复 census 已移除。** 原版单 worker 仍复现 14843.931ms，说明不能归因于全量并发才触发。真实 worker 对照中，旧实现用 843 次同步读与全仓 AST 分析生成最终仅依赖 registry 的 receipt；新实现直接调用扫描器原本使用的 buildStartupReceipt，仅读一次 committed JSON。完整 census 仍由 persistence-store-registry 测试覆盖，scanner、inventory、startup receipt 基线均未改。
3. **Xingye 源码读取保持同一覆盖。** 同目录、同扩展名和排除条件下改为每批最多 8 个异步读取；730 与 329 个文件的路径、顺序、内容 SHA 全部相同，IO 错误不吞。原生产约束断言不变。

历史扫描额外长停顿的 OS 原因仍未完全确定。独立 Node 原扫描约 1041ms，同步源码读取累计约 149ms；有效 worker 对照为 startup 1626.097→0.790ms，Xingye 两项 285.645→102.581ms、68.448→64.748ms。该对照先原后新，存在暖缓存顺序偏差，不能据此声称历史 18 秒/12 秒全部由磁盘造成。旧全量两个扫描与 OAuth 文件确有时间窗重叠，这只是并发事实。首个 Vitest preload 只覆盖主进程，不能拿它的 FS 计时解释 worker；另一次 OAuth --import Windows 路径错误在执行用例前失败，修正为 file URL 后才跑原八项。这些失败和限制均保留。原首项 4140ms 是整个 Vitest task（含 hooks/assertions），不是纯 builder 耗时；纯函数独立 cold/warm 为 8.628/0.153ms。

## Azure：复现、遗漏审查与最终修复

未修复的 `azure + openai-completions` 在显式 base_url/key 下仍进入 1.0.3 新 builtin；环境 endpoint/resource/deployment 覆盖模型地址/名称，显式假 key 被沿用。合成例的最终 URL 为 synthetic-environment.openai.azure.com、model 为 synthetic-env-deployment；custom-azure/completions 对照保持配置地址。Responses 的共同 resolver 也受影响。校正后的 baseline 为 34/58 路由失败、零网络尝试。首次 58/58 失败还混有 24 条 JS undefined 与 JSON 省略差异造成的驱动误判；原证据保存，未算成产品问题或删除失败。

首版 ModelRuntime 修复的两次 58/58 通过不足以关闭问题。独立审查发现 Hana 根导出的 raw completeSimple 也经 Pi compat 的 builtin 名称/API 选择器，真实 side-task 未传 streamFn 时可绕过保护。该同源遗漏另行实测：两 API × 两入口 4/4 失败；同一合成 probe 修后 4/4 通过，均零网络。旁路可达，但不声称每个正常会话都会走回退。

最终在 model-runtime.ts 共享 configuredAzureRequestEnv：有显式 Azure model.baseUrl 时添加请求作用域的 endpoint/resource/deployment 默认值，阻止仅因名字碰撞继承进程环境；显式调用 options 仍可覆盖。Pi 使用 || 回退环境，因此用有注释且经实际请求验证的空白 sentinel 阻止环境 deployment map 回灌。无自定义地址的 builtin 保持原行为；runtime 原生和匹配 legacy stream 扩展动态排除；refresh 使用最新 model 地址。index.ts 的 completeSimple 包装复用同一 helper，保留 typeof rawCompleteSimple 泛型签名、所有 options 及异常行为。生产代码不修改全局环境。

最终 Azure fixture 每次有 **74 条最终 HTTP 请求断言，仍计作一个 Vitest wrapper 用例**：原 58 条涵盖两 API×三 ID×五种环境、stream/complete、caller env、refresh 和 builtin；另加根导出 6、真实 side-task fallback 6、raw caller 2、raw builtin 2。原三身份、JSONL/history、tool call/reasoning IDs 断言保留。两次 fresh-home 最终矩阵均 74/74，通过、零网络；观察 JSON 同 SHA `634e6cfcc400523c7790f86d816d05280016fc68fd40584f30a8fc5dd054ea39`。没有读取真实 provider 环境值或凭据，没有真实外网请求，**不据此声称发生过真实凭据泄露**。

实测范围不包括所有调用配置：命名 azureBaseUrl/azureResourceName/azureDeploymentName options、并发 Azure 请求与 stored credential env 组合未直接作为独立矩阵验证；审查核对了相关环境合并源码，不把源码核对写成这些组合实测通过。
