# Facts authoritative read: persistence compatibility

Classification: **compatible error-handling correction**, relative to `79f900778dbb2f35cf968d4f23459980b33070f5`. DATA_EPOCH remains **1**. No dependency, SQLite schema, path, required field, migration, ownership, checkpoint or restore policy changes.

`compileEditableFacts` now uses the existing module-local `readSourceFile` helper for the authoritative merge baseline. Only `ENOENT` produces an empty baseline. All other errors propagate unchanged before the model call and before publication of Facts or its incremental watermark. The existing ticker records a failed Facts step without completing its daily checkpoint; a subsequent eligible attempt can consume the unchanged pending delta. The compiler itself neither swallows the failure nor schedules a new retry.

Readable Markdown is normalized as before. The first-use baseline initialization branch, `editable-facts-state.json` shape, summary filtering, no-fact-delta path, successful model merge, cancellation behavior, reset fencing and completion-order publication of concurrent compiles in the same reset generation are unchanged. Truly missing files still follow the established initialization path; an `ENOENT` at the later merge read remains an allowed empty baseline. The global `safeReadFile` helper, Today, Longterm and legacy migration behavior are unchanged.

The authoritative-read failure test starts from an existing Facts file and valid watermark with pending summaries. It verifies original error identity, zero model calls, exact retained body/state bytes, retry input containing the trusted baseline and pending delta only, and no repeat consumption after success. Additional synthetic tests cover `EIO`, `EACCES`, another non-ENOENT code and an error without a code, the real ticker's failure/retry checkpoint, missing-file controls, model failure/cancellation, reset and same-generation concurrency. All files are temporary fixtures and all model calls use a fake provider boundary.

This correction does not reconstruct previously lost facts, repair malformed state, make body/state writes a cross-file crash transaction, or change concurrent manual-edit handling. Existing checkpoint/restore guidance remains binding. Code rollback preserves file readability but reintroduces the read-error overwrite defect; it cannot recover previously overwritten content. No automatic rollback, data restoration, archive consumption or shared-home downgrade is authorized by this review.
