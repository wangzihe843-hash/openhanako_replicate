# First-run public persona ownership

The existing `ensureFirstRun` default-agent seed copies a packaged public persona to `agents/hanako/AGENTS.public.md` when a template exists. The copy site is classified under `agent-profile`; the remaining exact first-run exemption retains its 2026-11-17 expiry. The inventory still has 905 sites, and this classification moves one site from the exemption without changing other site mappings.

Server startup resolves `HANA_HOME` using `shared/hana-runtime-paths.ts`, which re-exports the actual `shared/hana-runtime-paths.cjs` implementation, and passes the result to `ensureFirstRun`. The executable CJS module is now bound to the three schemas already binding the server startup source: `agent-profile`, `user-preferences`, and `server-runtime-info`. Ignoring the supplied input changes each of their fingerprints; comment-only changes do not. This is whole-module executable fingerprinting, so changes to its other exported helpers also require review. The resolved root is shared by other stores and processes; this targeted binding does not claim that every dependent store's individual schema now fingerprints the resolver.

This is a compatible classification and fingerprint coverage change: runtime code, paths, formats, DATA_EPOCH, checkpoint and restore policies are unchanged. The seed chooses the freshly written config locale, then existing preferences locale, then English; non-Chinese locales try the English template before the generic template, and missing templates cause no copy: an absent target stays absent and an existing target remains unchanged. Normal repeated startup with a valid default agent does not reseed it. Repair of a missing or unreadable default config can copy over an existing public persona; an unreadable config is backed up. The direct copy is not an atomic or recovery guarantee: a failed copy may leave a partial target which a later normal startup does not repair. Concurrency and other readers' behavior are unchanged.
