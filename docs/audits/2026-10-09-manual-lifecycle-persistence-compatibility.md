## Separate ustar change and inventory receipt

`shared/artifact-core/ustar.cjs` already promises regular files as `0644`, executable files as `0755`, and directories as `0755`. Its creation modes were filtered by the caller's umask; after completed writes the repair applies the same normalization explicitly, including empty files. No archive path, header, content, accepted type, signature, artifact manifest, pointer or persisted schema changes. The two new subprocess regressions exercise `0077` and `0000` only inside isolated child processes and verify that the parent umask is unchanged. They also check removal of special/group-write bits and exact synthetic content. Windows retains the existing POSIX-specific test exclusion.

The official inventory comparison finds exactly one excerpt update: the existing `generic-archive-writer` site changes from `fs.createWriteStream(destPath, { mode: isExecutable ? MODE_EXECUTABLE : MODE_REGULAR, })` to `fs.createWriteStream(destPath, { mode })`. Its source file, ordinal, operation kind, classification and exemption are unchanged. The new `chmod` does not add a site under the existing scanner rules. This codec is not a guarded schema/protocol source; its permission repair does not change the schema payload. The inventory was regenerated by the official scanner, and belongs with the separate ustar patch. The startup receipt remains identical.
