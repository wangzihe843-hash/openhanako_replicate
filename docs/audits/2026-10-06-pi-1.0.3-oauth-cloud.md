**这是一份待 Windows 实机接入的云端候选，尚未 commit、push、发布或生成经验证的 Windows 安装包。** 本轮没有访问真实 OAuth 账户、刷新真实令牌、调用真实付费模型、迁移个人历史或修改系统权限。所有 provider、账户、会话与签名验证材料均为隔离的合成数据。

## 上游依据与根因对照

[官方修复 bde882c](https://github.com/earendil-works/pi/commit/bde882c7471c47dc31af3c622496df66c4fae010) 包含于 [Pi 1.0.3](https://github.com/earendil-works/pi/releases/tag/v1.0.3)。普通 auth 和 model-list refresh 共用修复后的凭据刷新函数：等待凭据锁时仍响应调用方取消；进入锁、开始可能轮换 token 的刷新后，只使用独立的原 15 秒 timeout；返回的新凭据先持久化再释放锁。调用方原有取消 race 保留，因此取消不必等待后台刷新完成。

05:59 UTC 在未修改的 1.0.2 上，用 Hana AuthStorage → ModelRuntime 和真正的文件后端复现：假 provider 已返回新 pair，然后调用方取消；调用收到 AbortError，文件却保留旧 refresh token。无取消对照正常保存新 pair。该基线脚本退出 0 表示成功观察到旧 bug，不能当成修复通过。

1.0.3 实测覆盖：

1. 提前取消，不刷新、不写凭据
2. 等待已占用文件锁时取消，调用及时返回，不发刷新
3. 刷新中取消，调用先结束，刷新 signal 仍有效，新 pair 最终保存
4. callback 返回到写盘之间取消，仍保存新 pair
5. 正常刷新与新鲜凭据不重复刷新
6. provider 失败保留旧值，释放锁后可重试
7. 真实、合作式 15000ms 刷新 timeout，之后可以重新获得锁并刷新
8. auth 阶段取消不进入模型 provider，仅一个终止事件，零模型 dispatch
9. 两个调用者、两个 OS 进程争抢，只消费旧 refresh token 一次
10. 原两个进程退出后，第三个全新 OS 进程从文件读取新 pair，无再次刷新
11. model-list 取消、被新一代刷新替代及过期 publication 拒绝
12. 额外使用产品实际 `AuthStorage.create(authPath)` 缓存读取路径验证三项：取消后持久化、真正的 refresh-modify 锁等待取消、两个缓存实例争抢。受控锁等待取消样本约 0.10ms 返回，不能推广为性能保证

八项 Node 取消测试、五个独立并发/目录场景及三个 Azure 身份是三项 Vitest wrapper 内的覆盖，不能再叠加到全量测试计数中。额外 cached-store 三场景是单独收据。所有网络陷阱计数为 0。

## 兼容性核查

### Azure 与持久化

官方 1.0.3 把内置 provider ID 从 `azure-openai-responses` 改为 `azure`，API protocol 字符串仍为 `azure-openai-responses`。Hana 自己的 ProviderCatalog → ProviderRegistry → syncModels 路径完整投影自定义模型，不能盲目重命名用户的 provider 身份。

在 1.0.2 与 1.0.3 上分别验证 `azure-openai-responses`、`azure`、`custom-azure`：身份、API、合成凭据和 v3 JSONL 模型恢复一致；同模型签名 reasoning ID、tool call ID、item ID 精确保留。最终仓库 fixture 还验证 catalog、models.json 和 JSONL 读取后的原始字节不变。本轮没有增加不必要的持久化迁移。上述结论针对这些 Hana 配置路径，不替代对其他来源的纯 Pi CLI 配置或任意旧数据的迁移审查。

八个关键已安装 SDK 源文件在 1.0.2/1.0.3 间逐字节相同：Agent、Agent loop、AgentSession、SessionManager、compaction、sdk、model-registry、provider-composer。实际 SDK 的历史/context_edit/重复 compaction/工具 outcome 与 structuredContent 回归另外执行通过，未仅用静态相同代替运行验收。

SDK 合成长输出 spill 也独立通过：完整 structuredContent、落地字节一致、一次 stub 操作、零 fetch；Linux 文件权限为 0600。此权限结果不冒充 Windows ACL 验证。

## 回退

代码回退应成套撤销本次依赖、锁、只读 guard、打包 pin、派生文件和对应测试/审计变更，并从旧锁重新干净安装、重新构建；保留独立的 README 提交及用户改动。可先 `git apply -R --check` 审核反向 patch，不能用 reset/clean 丢弃其它工作。

**不要用旧 auth.json 备份回滚 refresh token。** 已失效的旧 token 不会因文件恢复而复活。保留最新有效凭据；若既有凭据已经失效，只能由用户正常重新登录，不能靠本升级还原丢失的 token。
