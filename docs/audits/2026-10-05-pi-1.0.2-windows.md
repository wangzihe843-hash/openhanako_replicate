# Pi 1.0.2 Windows validation

The frozen Pi 1.0.2 candidate passed the applicable Windows regression, build,
packaging and isolated runtime gates. The retained API fixture configuration
failure was corrected in the temporary driver. The original open smoke and one
calibrated API run exceeded their unchanged readiness deadline; subsequent runs
passed without a product change or relaxed assertion. Their startup-duration
variance remains unattributed. The evidence supports the successful runs below,
not a guarantee that every first launch finishes within sixty seconds.

## Installation and release age

Validation used Node 24.15.0/npm 11.12.1 and the existing npmmirror registry with
`min-release-age=1`. The isolated clean installation was reused after matching
the final source/lock and rechecking every installed manifest. The project's
original node_modules was not reinstalled.

The isolated tree contains 1233 external packages, all matching the lock and
verified publication ages. All eight Pi/chord family entries are 1.0.2. Its
thirteen brace copies are eight 1.1.21, four 2.1.7 and one 5.0.12; no old Pi
shrinkwrap or 5.0.9 copy remains. The source lock SHA256 is
`2ac6ff0d53fb00ec94f119852e540c8d1609b283793d51733d8cde81e27458f3`.

The original resolution checked 1241 version pairs, including twelve new pairs,
against the one-day cutoff; its youngest new version was already 24.2377 hours
old. The fresh full/open production builds each resolved 64 additional pairs,
all at least one day old at their respective build starts. Actual pruned trees
contain 525/522 packages, match their locks, retain the Pi trio 1.0.2 and contain
only brace 1.1.21/2.1.7/5.0.12. Registry timestamps and actual manifests are
retained, rather than relying only on lockfile declarations.

## Retained failures, calibration and limits

The first API driver omitted the provider in its model selectors and received
`409 no_available_model` before any model request or business assertion. The
temporary calibrated copy supplies `{id, provider}` and adds current/isCurrent
preconditions. This was a driver error; the existing product configuration
contract was unchanged.

The first open smoke timed out before discovery readiness. Its old observer
matched the wrong fixture path, so child logs were unavailable. The corrected
observer only adds data listeners and lifecycle logging; it does not replace
spawn, intercept signals or change deadlines. Its positive/negative rerun passes
under the original sixty-second deadline.

The first calibrated API run also failed the sixty-second readiness gate. Its
server published discovery at 70.642 seconds, was normally shut down through its
own authenticated API, and remains recorded as a failed run. The next fresh-home
run passes all eight checks with unchanged assertions/deadlines. Original
failure receipts, separate cleanup timing and calibrated driver hashes remain in
`packaged-pi-api-receipt.json`, `packaged-pi-api-calibrated1-receipt.json`,
`packaged-pi-api-calibrated1-cleanup.json`, `harness-calibration-receipt.json` and
`api-calibrated2-input.json`. No product startup fix or established root cause is
claimed. Stage-one Pi 0.87.1 validation also recorded an initial open-smoke timeout
followed by a passing observed rerun; that is context, not a substitute for the
current tests.

The complete post-build source comparison inspects 3834 tracked paths: ten
tracked candidate files, 2255 byte-identical noncandidate files, 1568 existing
LF-only differences and one derived fixture icon. `generate-windows-icon.cjs`
rebuilds icon.ico from the unchanged PNG; its output equals the previous accepted
Windows fixture. Project icon SHA256 remains
`96b709911d033e13f7042a141db102e725895b4464ec2dc9bafcb9930bbef48a`;
fixture output is `da9e82034c62e2b16aad1164e435172f828dced8b3c70df7ba25eb190f85ce6e`.
It is not copied into this patch. The strict whole-fixture equality probe's
initial failure and the subsequent complete difference inventory are disclosed
in `post-build-fixture-source-differences.json`.

TZ=UTC was explicit. Unchanged timezone-sensitive fixtures have a documented
America/Los_Angeles limitation in the cloud checkpoint; this run does not certify
all timezones. Homes/workspaces contain synthetic data, with whitelisted OS
environment and no inherited model credentials. No ACL/owner/security-mode
change, real-user data effect, old prohibited retry UI/API action or previously
platform-blocked additional security sample was attempted.
